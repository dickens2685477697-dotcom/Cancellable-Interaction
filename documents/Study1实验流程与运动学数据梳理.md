# Study1 实验流程与手部运动学数据梳理

整理日期：2026-10-29  
依据：当前工作区的 `Assets/Scripts/Study1`、`Assets/AcceStimulate.cs` 和 `Assets/Scenes/Study1.unity`。本文是代码审阅记录，不等同于已执行实验的最终协议或结果。

> 更新说明：第 2–5 节保留原流程和采样方式的历史审阅。当前 Study1 场景已改用 MRTK 更新事件，并改为停留后撤回的任务；请以文末第 7–8 节为准。

## 1. 实验目的与范围

实验关注用户**有意选择目标时的手部运动**，重点观察食指尖进入目标区域以后，速度及其变化率随时间的变化。实现中通过起始球和目标球组织重复动作，并将目标区域内的运动样本写成 CSV，供后续按试次分析。

代码中存在自由停留和固定倒计时两套流程。静态场景中，启用的 `ExperimentCounter` 位于 `BackTrace/BackTraceButtonPass/FastTapIn`；固定倒计时的 `S1ButtonBehavior` 实例则位于未激活层级，或自身被禁用。因此，下文以自行停留流程为场景初始配置，并保留另一套流程供核对；运行时脚本可能改变对象状态。

## 2. 实验流程

### 2.1 自行决定停留时间的任务

1. 任务提示为 “Use your own dwell time to trigger the ball”，即参与者按自己的停留时间进行目标选择。
2. 参与者先将食指尖移入起始球；起始球标记试次已开始。食指离开起始球后，起始球隐藏。
3. 参与者将食指尖移入目标区域，目标材质变浅；区域内的每次有效采样可触发记录。参与者按自己的方式完成选择并移出目标区域。
4. 食指离开目标区域时，如果起始状态有效，目标的退出事件使计数增加；目标恢复原材质，起始球复位，准备下一次。
5. `ExperimentCounter` 默认 `MaxCount=10`，达到后进入冷却和下一任务；当前启用的下一任务显示 “Thanks” 并禁用目标检测。不触发／撤回任务在代码中被注释。默认冷却为 1 秒，场景中的对应序列化值也是 10 次、1 秒。

这里的计数依据是满足条件的目标 **OutEvent**，不应直接当作系统成功确认的次数。实际触发方式和阈值还取决于对象上 `AcceStimulate` 的模式与场景配置。依据：`StartBallBehavior2.cs`、`ExperimentCounter.cs`。

### 2.2 固定倒计时的另一套流程

1. 食指先进入并离开起始球，建立开始状态。
2. 进入目标区域后，启动倒计时，界面提示保持不动；倒计时完成后提示移开。
3. 提前离开会停止倒计时并给出警告；完成后离开则增加完成次数、重置状态并进入下一次。
4. `S1ButtonBehavior` 中累计 10 次后禁用检测并显示结束。`S1Clock` 的代码默认倒计时为 3 秒，但场景可以覆盖；场景中至少有一个时钟序列化为 5 秒且组件禁用，不能据此认定整个实验统一为 3 秒或 5 秒。

这套固定等待任务会影响参与者进入目标后的自然运动，解释数据时应与自行决定停留时间的任务分开。依据：`StartBallBehavior.cs`、`S1ButtonBehavior.cs`、`S1ButtonBehavior2.cs`、`S1Clock.cs`。

## 3. 数据如何采集

`AcceStimulate` 在 `FixedUpdate` 中通过 MRTK 获取 `Handedness.Any` 的 `IndexTip` 姿态；即这里测量的是**食指尖**，而不是整只手或手腕。首次有效姿态用于初始化，不生成运动样本。项目固定时间步长配置为 0.02 秒，名义上每秒 50 次固定更新，实际有效样本还取决于跟踪和运行状态。

| 指标 | 当前代码计算或记录的含义 |
| --- | --- |
| 速度 `v` | 相邻食指尖位置的欧氏距离除以固定时间步长；是非负的标量速率。 |
| 加速度 `a` | 相邻标量速率的差除以固定时间步长；是速率变化率，可为正或负，并非三维加速度向量。 |
| 区域内时间 `UpdateT` | 当前进入后的累计时间；日志写入发生在当次累加之前，因此第一条通常从 0 开始。 |
| 区域判定 | `Collider.bounds.Contains` 判断食指尖是否在碰撞器的轴对齐包围盒中，而非严格判断其是否在球形体积内。 |

当食指尖处于包围盒内，代码每次有效固定更新调用 `InEvent`；`LogWriter` 监听此事件并追加一行。退出后触发 `AfterOutEvent`，日志试次号增加。需要注意：跟踪失效期间不产生样本，恢复后上一位置没有重置，可能把跨失追的位移按一个固定时间步长计算，形成异常值。依据：`Assets/AcceStimulate.cs:141`、`ProjectSettings/TimeManager.asset`。

## 4. 输出数据与可分析内容

日志路径为 `Application.persistentDataPath/Logs/<时间戳>/<时间戳>-<对象名>.csv`；实际绝对路径取决于运行平台。每个对象独立创建文件，列为：

| 列名 | 含义 |
| --- | --- |
| `Case` | 本对象的进入／退出序号，初始为 1；每次 `AfterOutEvent` 后递增。 |
| `RunTime` | 写入时的 Unity `Time.time`。 |
| `Object` | 对象名称。 |
| `EnterTime` | 区域内累计时间 `UpdateT`，不是绝对入球时间。 |
| `Velocity` | 食指尖标量速率 `v`。 |
| `Acceleration` | 标量速率变化率 `a`。 |
| `Condition` | 触发判定代码使用的状态字符；含义依所选模式而定，不能直接作为参与者意图标签。 |
| `PrepTime` | 代码中准备状态的累计时间，是否有意义取决于模式。 |

`LogWriter` 在试次号递增到 16 时禁用对象，即最多记录前 15 次离开对应的序列；其他流程可能更早结束，例如计数器的 10 次。两者是独立限制，不能把 15 次当作该场景必然的实验试次数。日志按实际进入／退出分段，不保证每段都是有效选择。

围绕研究目的，可以按对象和 `Case` 将样本对齐至 `EnterTime=0`，绘制每次进入后的速度和速率变化率曲线，再计算进入后不同时间窗口的平均／峰值速度、最低速度及其出现时间、负变化率和停留时长，并在标注有效试次后比较参与者或条件。试次末尾的时间只反映最后一条区域内样本，不能精确代替离开事件时间。

当前 CSV 不包含原始三维位置、运动方向、左右手、跟踪质量、明确的选择成功事件或球外轨迹；因此不能仅凭这些字段重建轨迹、计算方向性加速度，或可靠识别用户何时形成选择意图。若需要比较进入前后、识别实际确认时刻或排除失追异常，应补充原始位置、左右手、跟踪有效性、进入／退出及确认事件和时间戳，并记录参与者、条件及构建版本。

## 5. 当前实现的边界和运行前核对

- `DataAnalysis.cs` 和 `S1ButtonBehavior` 中的 `DataAnalyze()` 是空实现；现有代码完成的是采集与写入，尚未实现上述统计分析。
- `Study1.unity` 包含多组实验组件；运行时激活状态、预制体引用和配置会影响实际流程。正式描述实验前，应在 Unity 中核对实际启动的场景、启用对象及其 `AcceStimulate`、计数器、时钟和 `LogWriter` 的 Inspector 值，尤其确认实际采集对象上的日志组件已启用。
- `InEvent` 在区域内每次固定更新触发；固定倒计时流程中它会反复调用 `StartCoroutine`，应在运行时验证倒计时是否符合预期，不能仅依据代码意图认定计时稳定。
- 区域采用包围盒、仅保存球内数据，且失追后的差分可能产生异常；这些限制会影响入球时刻、速度峰值和试次质量的解释。

## 7. 采样改造（2026-10-29）

`Study1.unity` 中的 `AcceStimulate` 改为订阅 Study3 共用的 MRTK 关节更新源。每次处理的关节快照来自同一次应用回调，速度用相邻接受更新的位置差除以其应用接收时间差；重复或倒序更新不会推进计算。失追、来源变化或样本过期时清除运动基线，不将中断当作正常离开。首次位置及首个速度样本分别标注速度和加速度有效性。

时间是应用收到 MRTK 更新的实时钟时间，并非已验证的硬件采集时间；每次 MRTK 更新也不保证对应独立硬件帧。`Acceleration` 保留 Study1 原有的带符号速率变化率，用于保持既有判定语义，不能与 Study3 部分新模式的三维向量加速度模直接等同。计时使用更新间隔并考虑 Unity timeScale；区域仍使用碰撞器包围盒。

Study1 的球内日志以 `-mrtk.csv` 结尾，在原列后追加 `Segment`、来源 ID、跟踪代、更新序号、回调接收时间、间隔和速度／加速度有效性，以及每个 MRTK 关节的位置和有效性。缺失关节留空，不移动后续列。`Segment` 在正常离开或球内跟踪中断后变化；中断不作为成功选择。第 8 节所述改造另加入了连续日志与试次事件日志。

该改造不改变历史 CSV；新旧数据不能视为同一采样规则。实际运行前应在 Unity 和头显上验证 MRTK 事件、场景启用、日志路径、追踪丢失恢复及试次流程。

## 8. 当前实验流程（2026-11-02）

以 Magic-Tap 论文 Experiment 1 为参考，参与者触碰起始球后进入目标球；食指进入目标区域时胶囊立即显示 `Hold` 倒计时，达到停留时间后提示撤回；正常撤出才计为一次完成。默认停留 3 秒、完成 20 次。目标对象 `ExperimentCounter` 组件的 Inspector 中可以调整 `Hold Duration`、`Max Count`；`End Capture Delay` 控制最后一次完成后继续记录的秒数，默认为 1 秒。界面提示保持，但程序按食指持续处于目标区域计时，没有对速度设置静止判定阈值。目标区域仍是碰撞器的轴对齐包围盒。

未达到停留时间提前退出或追踪中断时，该次不计完成，参与者应重新触碰起始球；保持满时间后退出才计数。记录不再因旧的 15 次退出上限停用目标。日志包含区域内 MRTK 数据、连续数据和试次事件，具体字段和终止时机以实际运行输出为准。连续记录涵盖目标外运动，最后一轮结束后持续 `End Capture Delay` 秒；开始和结束之间的数据需要结合事件时间划分。正式研究前应在头显中验证显示、计数、追踪失效与文件输出。

## 9. 目标空间固定方式（2026-11-04）

参照 Study3 正式场景的固定 `Spawner`：其世界位置为 `(0, 1.1, 0.537)` 米。Study1 的 `BackTrace` 是世界空间根对象，蓝色目标球中心相对它无偏移，现设置为 **`(0, 1.1, 0.53)` 米**：高度沿用 Study3，Z 坐标沿用之前的 0.53 米设置。运行时不会再根据相机或头显姿态覆盖此位置，头部转动也不会带动目标。实验者可在 `BackTrace > Transform > Position` 中调整位置。

这里的 1.1 米是**世界坐标高度**，不是自动测得的眼高；0.53 米是世界 Z 坐标，不保证为头显到球心的实际距离。实际差值受设备追踪原点、参与者坐姿和系统重置方式影响，应在头显中核对；系统重置不一定调整高度。

本轮实验绿蓝球心距离定为 **0.36 m**。`BackTrace > Study1 Head Anchor > Ball Center Distance Meters` 保存此值，场景开始时应用；蓝球位置不变，绿球沿目标前方移动。参数仍可在 Inspector 调整，但正式采集应保持本轮冻结值。两球直径均 0.06 m，球面间最短距离约 0.30 m。碰撞体通过包围盒判定进入，实际手指位移还取决于触碰位置和轨迹。`-session-layout.csv` 的版本 2 标记 `LayoutMode=world_fixed`，记录目标与起始球中心及实际球心距离；头显追踪数据可用时还记录头显到球心的实际距离、XR 头部位姿、MRTK 追踪空间和相机世界位姿。头显不可用时相关字段留空，不会阻止固定场景显示；这些字段不是连续头部运动记录。

接收到系统追踪原点变化通知时，当前未完成试次会中止，已完成次数保留；实验对象短暂隐藏后回到**原来的固定世界坐标**，不会移动到头部位置。程序监听 Unity XR 原点更新，在 Android 上也检查 Oculus 的重置计数。相关事件和新的布局快照分别写入事件及 `-session-layout` 文件；帧日志的 `ReferenceSpaceEpoch` 区分坐标空间，离线计算运动学时不能跨重置做差分。Quest 与 Quest Link 的具体重置操作和空间变化仍需真机验证。

此前目标跟头、按初始头显定位及其他位置配置的数据应与当前配置区分。正式采集前需在 Quest 中核对目标高度、与参与者的实际距离、起始球可见可达和坐姿舒适。
